# Scan-Art 설계 문서

- 작성일: 2026-09-25
- 의뢰: 평택특수교육지원센터
- 상태: 설계 검토 대기

## 1. 목적과 범위

학생 작품 전시에서 작품 옆에 QR 코드를 붙이고, 관람객이 스캔하면 해당 작품의 설명 페이지가 열리게 한다. 이 프로그램은 선생님이 작품 설명 페이지를 쉽게 구성하고 QR 코드를 생성·인쇄할 수 있게 해 준다.

### 사용자

| 구분 | 사용자 | 주 환경 | 하는 일 |
|---|---|---|---|
| 관람객 | 전시 방문자 | 스마트폰 (로그인 없음) | QR 스캔 → 작품 사진·설명·음성·영상 감상, 공유 |
| 관리자 | 센터 선생님 1~2명 | PC + 스마트폰 | 작품 등록·수정, 사진 촬영, 학생 음성 녹음, QR 인쇄 |

### 범위

- 포함: 일회성 전시 1개, 작품 관리, 관람 페이지, 전시 표지(작품 목록 포함), QR 생성·인쇄, OG 이미지
- 제외: 여러 전시 운영, 온라인 갤러리 별도 페이지, 관람객 반응(하트·댓글), 개인별 관리자 계정, 다크 모드

### 성공 기준

- 관람객이 QR을 스캔하면 모바일에서 불편 없이 작품 페이지가 빠르게 열린다 (LCP < 2.5s, CLS < 0.1).
- 선생님이 개발 지식 없이 휴대폰만으로도 작품 등록부터 인쇄까지 할 수 있다.
- 인쇄한 QR 주소는 작품 내용이 바뀌어도 변하지 않는다.
- 무료 플랜 안에서 운영된다.

관람·관리 화면을 하나의 Next.js 앱에 둔다. 관람 페이지는 ISR로 캐시하고, 저장 시 해당 경로만 `revalidatePath`로 갱신한다.

### 무료 한도 (2026-09 공식 문서 기준)

- Vercel Hobby: 월 Fast Data Transfer 100GB, Function 호출 100만, Active CPU 4시간, 이미지 변환 5,000회, Cron 하루 1회. 초과해도 요금이 청구되지 않고 기능이 제한된다. **비상업적 개인 용도만 허용** (개발자가 대가를 받는 경우도 상업적 용도로 간주).
- Neon Free: 프로젝트당 0.5GB, 월 100 CU-시간, 5분 동안 요청이 없으면 멈추고 요청 시 자동으로 깨어남, 외부 전송 월 5GB. 한도를 넘어도 데이터는 삭제되지 않음.
- Vercel Blob Hobby: 저장 1GB, 쓰기 작업(Advanced) 2,000회/월, 조회(Simple) 10,000회/월, 전송 10GB/월. **초과 시 30일 동안 Blob 접근 불가.** 따라서 업로드 전 리사이즈가 필수다.

## 3. 데이터 모델

### `settings` (1행)

전시명, 부제, 기간 시작·종료, 장소, 소개글, 주최(기본값 "평택특수교육지원센터"), 대표 이미지(URL·크기·blur), `updated_at`.

### `artworks`

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | text PK | nanoid 8자, 추측하기 어려움, 변경 불가, URL·QR에 사용 |
| `title` | text | 작품명 (필수) |
| `artists` | text[] | 작가 여러 명, 자유 입력 (실명 또는 단체명) |
| `material` | text? | 재료 |
| `size` | text? | 크기 |
| `description` | text | 설명글 (일반 텍스트, 줄바꿈 유지) |
| `audio_url` | text? | 녹음 파일 |
| `audio_duration` | int? | 녹음 길이(초) |
| `tts_enabled` | bool | 녹음이 없을 때 읽어주기 버튼 표시 |
| `youtube_url` | text? | 영상 링크 |
| `is_published` | bool | 공개 여부 |
| `sort_order` | int | 표지·이전/다음·인쇄 순서 |
| `created_at`, `updated_at` | timestamptz | |

### `artwork_images`

`id`, `artwork_id` (FK, cascade), `url_lg` (1600px), `url_sm` (800px), `width`, `height`, `blur_data` (32px WebP base64), `alt`, `sort_order`. 첫 번째 이미지가 대표 사진이다.

### `login_attempts`

`ip` (PK), `fail_count`, `locked_until`, `updated_at`. 로그인 시도 제한에 쓴다 (6장 참고).

### 파일 경로 (Blob)

- `artworks/{artworkId}/{uuid}-lg.webp`, `-sm.webp`
- `artworks/{artworkId}/audio-{uuid}.m4a` (또는 `.webm`)
- `settings/cover-{uuid}-lg.webp` 등

작품·이미지·녹음을 삭제하거나 교체하면 Blob 파일도 함께 `del()`로 지운다.

상태별 처리:
- 비공개 작품: "작품 이야기를 준비하고 있어요" 페이지를 보여준다 (QR을 먼저 인쇄해 붙여도 되게).

모든 페이지는 `noindex`로 설정하고 `robots.txt`에서 전체를 차단한다.

## 5. 관람객 화면 (모바일 우선)

### 작품 페이지 `/a/{id}`

1. **대표 사진**: 화면 높이 약 70%, 한지 액자 연출. 여러 장이면 좌우 스와이프 갤러리 + 점 표시. 탭하면 전체 화면 뷰어 (두 손가락 확대, 아래로 쓸어 닫기).
2. **작품 정보**: 제목, 작가 이름표(여러 명), 재료·크기. 스크롤하면 떠오르며 나타남.
3. **듣기**:
   - 녹음이 있으면 "작가의 목소리로 듣기": 큰 재생 버튼, 원형 진행 표시, 재생 중 물결 애니메이션.
   - 녹음이 없고 `tts_enabled`면 "읽어주기": Web Speech API, 읽는 문장 하이라이트. 한국어 음성이 없는 기기에서는 버튼을 숨긴다.
4. **설명글**: 넉넉한 줄 간격, 글자 크기 조절(가 / 가+), 선택값은 `localStorage`에 저장 (실패해도 동작).
5. **영상**: YouTube 썸네일을 먼저 보여주고, 탭하면 iframe을 로드한다 (lite embed).
6. **하단**: 이전·다음 작품 카드, 공유 버튼 (Web Share API, 지원하지 않으면 링크 복사 + 토스트).

### 전시 표지 `/`

전시명, 기간, 장소, 소개글, 공개 작품 카드 목록 (`sort_order` 순).

### 전환과 성능

- 목록 → 작품: 대표 사진이 이어지며 커지는 전환 (View Transitions API, 지원하지 않으면 Motion으로 대체). 나머지 내용은 순서대로 떠오른다.
- `prefers-reduced-motion`이면 모션을 최소화한다.
- 사진은 미리 만든 800/1600 WebP를 `srcset`으로 제공한다. Vercel 이미지 변환은 쓰지 않는다.
- blur 미리보기로 레이아웃 이동 없이 로딩한다.

## 6. 관리자 화면

### 인증

- 공용 비밀번호 1개, Vercel 환경변수 `ADMIN_PASSWORD`에 저장한다.
- 로그인에 성공하면 서명된 HttpOnly 쿠키 세션을 발급한다 (`SESSION_SECRET`, 유효기간 30일).
- `/admin/*`와 모든 변경 Server Action에서 세션을 검증한다.
- 로그인 시도 제한: 같은 IP에서 5회 연속 실패하면 5분 동안 막는다 (DB 테이블 `login_attempts`로 기록).

### 작품 목록 `/admin`

- 카드 그리드: 대표 사진, 제목, 작가, 공개 배지, 사진·음성·영상 유무 아이콘
- 드래그로 순서 변경 (`@dnd-kit`, 터치 지원)
- 공개 토글, 제목·작가 검색, 여러 개 선택 → 인쇄로 이동
- 모바일: 카드를 왼쪽으로 밀면 공개 토글·삭제 버튼 표시
- Blob 사용량 표시, 80%를 넘으면 경고

### 작품 편집

- PC: 왼쪽 폼 + 오른쪽 휴대폰 모양 실시간 미리보기 (관람 컴포넌트 재사용). 모바일: 폼/미리보기 탭 전환.
- **사진**: 여러 장 드래그·선택 업로드, 휴대폰 카메라 촬영(`capture`), 드래그로 순서 변경, alt 입력, 삭제, 사진별 진행률
- **녹음**: 녹음·정지·다시 녹음, 실시간 음량 파형, 들어보고 저장, 파일 업로드 대체. 최대 3분. 형식은 `audio/mp4`(AAC)를 우선하고 지원하지 않으면 `audio/webm`(opus)을 쓴다.
- **영상**: YouTube 링크 붙여넣기 → 썸네일 즉시 확인, 잘못된 링크면 안내
- **QR**: 작품별 QR 미리보기, PNG·SVG 다운로드
- **저장**: "저장" 버튼을 눌러야 반영된다. 저장하지 않은 변경이 있을 때 나가려 하면 확인 모달을 띄운다 (브라우저 새로고침·닫기는 `beforeunload`).
- 작품 삭제는 확인 모달을 거친다.

### 사이트 설정 `/admin/settings`

전시명, 부제, 기간, 장소, 소개글, 주최, 대표 이미지.

관리자 화면 전체가 모바일에서 불편 없이 동작해야 한다.

## 7. QR과 인쇄

- QR 내용: `${NEXT_PUBLIC_SITE_URL}/a/{id}`, 오류 정정 레벨 M, 가운데 로고 없음, SVG로 생성
- 현재 접속 주소(origin)가 `NEXT_PUBLIC_SITE_URL`과 다르면 인쇄 화면에 경고 배너를 띄운다.
- **인쇄 대상**: 전체 / 선택 / 공개 작품만
- **템플릿**
  - 명제표 카드: 한지 배경(켜기/끄기), 작품명, 작가, 재료·크기, QR, "스캔해서 작품 이야기 보기". 크기는 명함 90×50mm, A6 148×105mm, 정사각 100×100mm 중 선택.
  - QR 스티커: 30 / 40 / 50mm, 작품명 표시 여부 선택
- **A4 자동 배치**: 카드 크기와 여백으로 행·열을 계산하고 재단선을 표시한다. 화면에 실제 종이 비율 미리보기를 보여주고 페이지를 넘겨볼 수 있다.
- **인쇄**: `window.print()`, `@page { size: A4; margin: ... }`, mm 단위. 한지 배경을 켰으면 "배경 그래픽" 체크 안내를 띄운다.
- QR 인쇄 크기가 25mm 미만이면 경고한다.

- 원칙: `transform`/`opacity`만 애니메이션, 60fps, `prefers-reduced-motion` 존중, 터치 영역 44px 이상, 쪽빛 포커스 링

## 9. 이미지 처리 (모두 WebP)

- 업로드 전 브라우저 Web Worker에서 처리:
  1. 디코딩: `createImageBitmap` (`imageOrientation: 'from-image'`), HEIC는 필요할 때만 `heic2any`를 지연 로드
  2. 리사이즈: 긴 변 1600px, 800px, 32px(blur)
  3. 인코딩: `OffscreenCanvas.convertToBlob({ type: 'image/webp' })`. 결과 타입이 WebP가 아니면(Safari 등) `@jsquash/webp` WASM으로 대체
- 재인코딩 과정에서 EXIF(GPS 등)가 제거된다.
- Blob 클라이언트 업로드 토큰은 `allowedContentTypes: ['image/webp']`만 허용한다 (오디오는 별도 토큰으로 `audio/mp4`, `audio/webm`만 허용).
- OG 이미지: `next/og`, 1200×630 PNG, 한지 배경 + 대표 사진 + 제목·작가. Satori가 WebP 입력을 지원하지 않으면 OG 라우트에서 대표 사진을 PNG로 변환해 넣는다 (구현 시 확인). 최종 OG 이미지만 PNG로 예외다 (공유 미리보기 호환성).

## 10. 알림·확인 UI와 문구 규칙

- **`alert()`, `confirm()`, `prompt()` 사용 금지.** ESLint `no-alert` 규칙을 error로 둔다.
- 모든 알림은 디자인된 **토스트**로, 확인이 필요한 동작(삭제, 저장하지 않고 나가기 등)은 디자인된 **모달**로 처리한다.
  - 토스트: 한지 카드 스타일, 성공/정보/오류 색상 구분, 아래에서 떠오르는 모션, 스와이프로 닫기, 오류 토스트에는 "다시 시도" 동작을 넣을 수 있다.
  - 모달: 포커스 가두기, ESC·바깥 클릭으로 닫기, 모바일에서는 아래에서 올라오는 시트 형태.
- **모든 사용자 노출 문구는 자연스러운 한국어로 쓴다.** 영어 원문 오류, 개발자용 메시지(스택, 오류 코드, `Error:`, `undefined` 등)는 절대 보여주지 않는다.
  - 오류는 `lib/errors`의 오류 코드 → 한국어 문구 매핑을 거쳐 표시한다. 매핑에 없는 오류는 "잠시 문제가 생겼어요. 다시 시도해 주세요." 같은 일반 문구로 대체한다.
  - Zod 검증 메시지, 브라우저 권한 오류(마이크·카메라), 업로드·네트워크 오류, 404/500 화면 모두 한국어다.
  - 원본 오류는 서버 로그(`console.error`)에만 남긴다.

## 11. 오류 처리

| 상황 | 처리 |
|---|---|
| 사진 업로드 실패 | 사진별 오류 표시 + 다시 시도, 실패한 사진이 있으면 저장 불가 안내 |
| 마이크 권한 거부 | 권한 켜는 방법 안내 모달, 파일 업로드로 대체 |
| 지원하지 않는 녹음 형식 | 파일 업로드 안내 |
| DB 저장 실패 | 입력값 유지, 오류 토스트 + 다시 시도 |
| DB가 깨어나는 중 | 관리자 화면 로딩 표시 (관람 화면은 ISR 캐시로 영향 없음) |
| Blob 사용량 80% 초과 | 관리자 대시보드 경고 |
| 관람 페이지 오류 / 없음 | 한지 디자인의 `error.tsx`, `not-found.tsx` |
| 로그인 실패 | 입력칸 흔들림 + 오류 문구, 5회 실패 시 대기 안내 |

## 12. 테스트

- **Vitest**: 이미지 변환 파이프라인, A4 배치 계산, YouTube URL 파싱, 오류 코드 → 한국어 매핑(누락 시 실패), Zod 스키마, 세션 서명·검증, 로그인 시도 제한
- **Playwright**: 로그인, 작품 등록(사진·녹음 파일 업로드·영상), 공개, 모바일 뷰포트 관람 페이지, 비공개·없는 작품 페이지, 인쇄 미리보기, 다이얼로그(`alert` 등) 발생 시 테스트 실패
- **실제 기기**: iPhone Safari, Android Chrome에서 QR 스캔, 스와이프, 녹음·재생, TTS 확인
- **성능**: 모바일 Lighthouse LCP < 2.5s, CLS < 0.1
